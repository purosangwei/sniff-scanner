    What it looks for

    • Code that runs on npm install. The Binance attack started exactly this way: the test ran its payload during installation.
    • VS Code tasks that run when you open the folder. No install needed, just opening it is enough.
    • Hidden and scrambled code. Obfuscators, long encoded blobs, eval, code pushed off the edge of the screen.
    • Calls home. Bare IP addresses, paste sites, Discord and Telegram webhooks.
    • Hunting for your stuff. Wallet extensions like MetaMask and Phantom, saved browser passwords, SSH keys.
    • Dodgy packages. Lookalike names, packages published days ago, packages npm has taken down, installs from links or private servers.
    • Files that don't belong. Programs, native add-ons, code dressed up as fonts or images, hidden instructions for AI coding assistants.
    • The repo itself. Brand-new repos and accounts, one-commit histories.

    If a stranger sends you a test

    • Open it in a throwaway VM or cloud dev box, never on the laptop with your wallets or work logins.
    • Don't run npm install or open the folder in VS Code until you've scanned it and read package.json.
    • Check the company exists outside the chat: a real website that links to the same GitHub account.

    $SNIFF flags known risks. It can't promise a repo is safe, and neither can any other scanner.
