    What it looks for

    The tricks

    The ways any repo you download can run code on your machine, from fake coding tests to dodgy packages.

    • Code that runs on npm installThe Binance attack worked like this: the repo ran its payload during setup.
    • VS Code tasks that run when you open the folderNo install needed, just opening it is enough.
    • Hidden and scrambled codeObfuscators, long encoded blobs, eval, code pushed off the edge of the screen.
    • Calls homeBare IP addresses, paste sites, Discord and Telegram webhooks.
    • Hunting for your stuffMetaMask and Phantom, saved browser passwords, SSH keys.
    • Dodgy packagesLookalike names, packages days old, packages npm has taken down.
    • Files that don't belongPrograms, native add-ons, code dressed up as fonts, hidden orders for AI assistants.
    • The repo itselfBrand-new repos and accounts, one-commit histories.

    1Scan first

    Before you install anything or open the folder in VS Code. Both can run code on their own.

    2Use a throwaway machine

    Open it in a VM or cloud dev box, even if the scan comes back clean. Never on the laptop with your wallets, and never on a work laptop. That's how Binance lost $6.3 billion.

    3Check where it came from

    Who made it, and do they have a real history? A brand-new account or one-commit repo is a bad sign. So is anyone rushing you to run it.
